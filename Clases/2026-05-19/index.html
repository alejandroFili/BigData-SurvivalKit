    KSQLDB¶

    Nivel de almacenamiento : mensajes y topicos Nivel SQL tres abstracciones: - Connector: - borrar y crear conectores - dialecto tipico SQL para connectors - si creo un connector source - se empieza a producir mensajes. - si creo un connector sink - se empieza a consumir mensajes - streams - representa el flujo de los mensajes dentro de un topico - se pueden tener muchos funcionando a la misma vez - metafora: tubo por donde fluye el agua - siempre crear un raw_stream - que tipo - como parseo - interactua directamente con los mensajes - encadeno streams, transformando los datos - se puede crear pipelines a traves de streams - tablas - no tienen nada de ver con las tablas de SQL - es un estado concreto de un stream (o varios streams) - solo vale para hacer aggregados - metafora : ajedrez - https://docs.confluent.io/platform/current/streams/overview.html#related-content - mientras evalua se cambia

    Importancia de tener la tabla RAW; interpretar bien metadatos

    StopArrivalTime : Service ID : no puede ser nulo

    Queries¶

    3 tipos: - puramente continuas - PUSH - van contra datos en streams - EMIT CHANGES (da error si no la pones) - reciba mensaje con cada cambio - PULL - (como las tablas) - devuelven el estado actual y terminan - requieren tablas en estado materializado
