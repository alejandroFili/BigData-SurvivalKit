# Clickhouse

!!! quote " A gusto con gran volumen de datos "

!!! danger " Es importante notar los siguientes **aspectos principales**: "
>
>1. **No hay clave primaria** explícita (asume las columnas en _order by_)
>2. Consecuentemente, las claves primarias **no garantizan la unicidad**. Es decir, puede haber múltiples filas con idéntica clave primaria
>3. Todas las **escrituras son secuenciales e inmediatas**
>4. Almacena de manera **ordenada** ya que el reparticionado de los datos ocurre _en diferido_
>5. El valor del _TTL_ permite establecer un tiempo de **caducidad de los datos**

### MergeTree (familia de motores)

Basado en arboles LSM.

!!! quote " Las tablas se dividen en grupos de filas (particionado horizontal), fusiona en background. "

Ejemplos : 
- AggregatingMergeTree
- ReplacingMergeTree

!!! quote " Cada fragmento tiene normalmente su propio directorio y los datos se organizan de forma colmnar ordenados segun la clave primaria (¿?¿) - se parece a parquet con hive. Primero hace horizontal y despues vertical (verificar) "


!!! danger " ORDER BY : no es una clave de ... es una clave de ordenacion "

```SQL
CREATE TABLE ejMergeTree ( id UInt16, created_time Date, comment String ) 
ENGINE = MergeTree() 
ORDER BY (id, created_time) 
PARTITION BY toYYYYMM(created_time) 
TTL created_time + INTERVAL 3 MONTH;
```

!!! danger " Los datos pueden caducar. TTL (no es obligatorio) -  permite seleccionar ventanas de analisis (basadas en tiempo-) "

> [!Danger] Vas por bloque no por fila

!!! danger " Los bloques, además de los datos, contienen los metadatos de manera que no se requiere un catálogo de metadatos "
